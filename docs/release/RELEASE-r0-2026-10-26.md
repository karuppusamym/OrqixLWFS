## How to deploy

- **Compose (demo, test, small installations):** `deploy/compose`, or `tools/demo/demo-stack.sh up <tag> [port-base]` for an isolated stack with seed data ([demo guide](../demo-guide.md)).
- **OpenShift:** `deploy/openshift` (kustomize base and overlays; the manifests name the image `orqix`, so set the tag `r0-2026-10-26` in your overlay). See its README.
- **Settings and secrets:** [admin guide](../admin-guide.md), including the new "Scaling and capacity" section.

## Upgrading an existing database

1. Back up the database first. Migrations are forward only; **rollback means restoring the backup**, not running anything down.
2. Run the migration job (it applies every missing version in order). Out-of-order migrations are **off**: the schema is expected to arrive at `V155` through the numbered sequence. Numbers are not contiguous (for example `V123` to `V129` are unused); that is fine.
3. Never edit a migration file that has been released, not even a comment: Flyway checksums would then refuse to start the application on an existing database. Corrections go in a new migration.

## Known limits (read before production)

- **Not production-qualified:** no production identity provider, no production capacity figures, no high-availability database ([OPS05](../22-competitive-gap-delivery.md) and the external-input tickets stay open).
- **Scalability:** correct with several replicas, but throughput is database-bound. Starting requests is serialised per workspace by the gap-free `ORQ-n` counter, Insights is recomputed on each view, and the inbox count scans open tasks. Details and numbers in S92.
- **Transports are stubs:** adapter sends (email, Teams, Kafka, JDBC) and agent write tools deliver only to local stub transports. No live sends.
- **Pega:** the XPDL 2.0 subset and the synthetic Blueprint PDF are demonstrated. Compatibility with real Pega Blueprint PDFs is **not** claimed until a real sample is supplied. Native rule pages and source equivalence are not covered.
- **Still open epics:** WM04 (full CMMN) and UI02 (general application designer).
- **Regex engine:** form-field patterns use a purpose-written linear-time engine with a deliberately narrow subset; have it reviewed before relying on it.
- **Demo data and dev credentials** (`Dev!<username>`) are for development only and must never reach a real environment.
