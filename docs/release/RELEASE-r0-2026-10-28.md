## What changed since r0-2026-10-27

- **Studio layout:** the main menu sits behind the top-bar button while editing; the canvas has the width. **View** shows or hides the step list, the **Ask AI** dock (a chat-style composer under the canvas, with a **Talk** button for browser speech recognition) and the **Details and discussion** cards. **More** holds Preview, Explain and the exports; advanced settings are under **Advanced** headings in plain words; a nearly empty draft shows four tips. **Ask AI about this step** points an instruction at the selected step.
- **Ctrl+K Ask Orqix** on every page (jump to a page or hand a question to the Assistant; the question travels in router state, never the address). The Assistant page has side cards and dictation. List pages are unchanged by design.
- **Fix: the open-request limit is exact under concurrency.** Starts of one workflow now queue behind each other (`FOR NO KEY UPDATE`); before, 107 starts were accepted against a limit of 100 when eight callers arrived together. Mutation-checked test `tRun08b`.
- **Fix: Kafka triggers and webhook subscriptions switched off no longer count toward the per-workspace limit** (they cannot be deleted); re-enabling checks the limit; switched-off rows are bounded at five times the limit.
- Cases notice reworded; user guide, S100 and S101 notes added; new integration overlay (`tools/demo/integration.override.yml`) and end-to-end scripts.

## Upgrade notes

1. Back up first; rollback means restoring the backup. No schema change.
2. A single workflow now starts at about 14 per second in the test setup (it was about 22 with the unsafe lock) because starts of one workflow are serialized; starts were already serialized per workspace by the request counter ([S92](../build/S92-scalability-qualification.md)).
3. Everything in the r0-2026-10-27 upgrade notes still applies (Kafka mode off by default, webhook `v1=` signatures and the `webhook-` secret namespace, shared test assertions in the publish gate).

## Known limits

- Not production-qualified: no production identity provider, no production capacity figures, no high-availability database.
- Kafka was run against a plain-text single-node broker; TLS/SASL against a secured broker and a two-process consumer group on the Docker stack were not run (the consumer-group behaviour is covered by tests with two consumers).
- Throughput figures are one laptop, one database, one process. They show correctness and a floor, not capacity. The request counter, Insights recomputation and the inbox count remain the known database-bound points ([S92](../build/S92-scalability-qualification.md)).
- Voice dictation depends on the browser's speech recognition (Chrome and Edge) and was not exercised with a real microphone; some browsers send the audio to their vendor. The Ask AI conversation was not exercised with a live AI key.
- A list of earlier Assistant conversations is not offered because the server keeps one open conversation per person.
- Still open: WM04 (full CMMN import and discretionary planning) and UI02 (general application designer); real Pega Blueprint PDFs are unsupported until a sample is supplied; adapters and agent write tools deliver only to local stub transports.
- `PinnedWorkflows.test.tsx` failed once in some full frontend runs and passes when run alone (timing under load); it passed in the final full run.
