## What changed since r0-2026-10-29

- **Start throughput ([S103](../build/S103-start-throughput-and-loose-ends.md)):** the open-request limit no longer makes every start of a workflow wait (only within 64 of the limit), and the new setting `orqix.runs.reference-allocation=fast` takes the request number in its own short transaction. 200 concurrent starts of one workflow: 16.9 per second before, 53.6 with the default, 82.4 with `fast` (one laptop).
- **Archive a workflow** (Organize > Archive this workflow; refused while requests are open) and **delete a switched-off Kafka trigger or webhook subscription** (new migration V173).
- Merged the other session's work: CI fixes, code-review fixes (whole-word Assistant matching, dictation, call cancel, OAuth logs) and a simpler New workflow flow.
- Loose ends: axe scan of Home and Cases, the PinnedWorkflows test race, integration and bulk re-run, the demo's stale draft archived.

## Upgrade notes

1. Back up first, then apply **V173** (it only grants DELETE on two tables to the application role).
2. `orqix.runs.reference-allocation` defaults to `gapless` (no change). Set `fast` on **every** replica only if gaps in `ORQ-n` numbers are acceptable.
3. New problem code `RESOURCE_IN_USE` (409) for archiving a workflow with open requests and deleting a switched-on trigger or subscription.
